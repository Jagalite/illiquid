# Agent UI implementation contract

Internal integration contract for this implementation. The [user-facing runbook](../../Documentation/MACOS_AGENT_UI_AUTOMATION_RUNBOOK.md) records current usage and qualification limits.

Python stdlib CLI: `python3 Scripts/agent-ui/agent_ui.py COMMAND ...`. Each invocation emits one JSON envelope to stdout: `schema_version:1`, `status` (`ok`, `unsupported`, `permission-required`, `timed-out`, `target-lost`, `assertion-failed`, `error`), `data` object, optional `error` string. Diagnostics go to stderr. Non-ok results exit nonzero.

Run folder owns `manifest.json`, `actions.jsonl`, and artifacts. Manifest records run_id, PID, executable path/hash, process start identity, owned flag, bundle path/id, session token, control file, and environment. CLI commands after launch/attach use `--run-dir PATH`. Never select an app only by name. Attach is read/interaction authorized but close must not terminate unowned processes unless explicit option. No automatic production preference reset. The benchmark bundle has a shared preference domain; `CFFIXED_USER_HOME` does not establish per-run preference isolation. Do not claim isolated defaults or run concurrent preference-mutating scenarios.

Native helper: `Scripts/agent-ui/native.swift`, built by runner to a cache using swiftc. Reads exactly one JSON request from stdin, outputs envelope. Request `{operation, pid?, ...}`. Operations `doctor`, `inspect`, `act`, `capture`, `identity`. Default inspect data contains `windows` and flattened `elements`; `windows_only:true` performs read-only CG window discovery without an AX tree, returning `elements:[]`, `truncated:true`, `inspection_scope:"windows-only"`. Launch uses that probe only after channel readiness and exact-process activation. Selector-free accessibility focus waits for frontmost ownership while pumping the run loop, then verifies AX focus. These milestones do not establish layout or presentation. Default element fields include `id` (ephemeral path), `identifier`, `role`, `label`, `value`, `enabled`, `focused`, `bounds:{x,y,width,height}`, `window_id`. Act request `{operation:"act",pid,action,mode:"input"|"accessibility",target?:{identifier?|id?|window_id?},...}`. Supported primitives click/double-click/right-click/hover/move/drag/scroll/type/key/menu/focus/window. Drag `from:{x,y}`, `to:{x,y}`, `duration`; click optional `point`; points in `quartz-global-logical-points`. AppKit window snapshots and SwiftUI diagnostic grip bounds declare different coordinate spaces; no grip-to-global mapping is currently qualified. Key `key` string and `modifiers` list. Window action `window_action` + optional frame. Reject unsupported actions explicitly, never silently use AX when input requested. Re-resolve tree/targets each invocation; return ambiguous target error. Bound inspection depth/elements and timeouts. Identity works without AX permission and reports executable path, process start identity if possible, bundle_id, alive. Capture to request `output` path, only owned target window.

Trace adapter: standalone `Scripts/agent-ui/trace.py`, Python stdlib, CLI `doctor`, `start --run-dir PATH --pid PID --template NAME --seconds N`, `stop --run-dir PATH`, `export --run-dir PATH`; JSON envelopes same as above. The runner wrapper reserves minimum outer deadlines of start=240s, stop=60s and export=120s; these include cleanup time and shorter CLI values fail. Persistent recorder ownership metadata, bounded operations, preserves raw trace and export errors. No fabricated frame metrics. Exports discover table of contents and summary of availability; unsupported/empty required data is not passing. Test module uses fake subprocess or fixture exports, no live profiling alongside other validation.

Benchmark app changes: extend existing guarded BenchmarkPlaybackControl commands with `capabilities` and `agent-state` through AppModel. Existing session/id and command transport remain. Structured JSON state emitted with a distinct `[agent-ui-state] ` line correlated by session/id; don't remove existing acknowledgements. State includes playback/chrome/source revision/window/readiness and diagnostic custom targets if feasible. No arbitrary eval or ungated production channel.

Scenario JSON v1: `{schema_version:1,name,description?,requires?:[],steps:[{id,command,args,expect?}],metrics?:{required:[]}}`. Commands `inspect`, `act`, `hook`, `wait`, `assert`, `capture`, `trace-start`, `trace-stop`, `trace-export`. args object follows native request for act; hook `{action,...}` existing benchmark command fields. Assertions `{path,op:"eq"|"ne"|"exists"|"gt"|"gte"|"lt"|"lte"|"contains",value?}` resolve against last command envelope; wait args `{command:"inspect"|"hook",args:{...},condition:{path,op,value},timeout,interval}`. Defaults bounded. Scenario runner must fail on missing metrics/capabilities or unsupported steps, save actions and report. Examples must explicitly indicate fixture/setup requirements. No claim of fully automated coverage for unimplemented families.

All agents share checkout. Own only assigned files. Do not stage/commit/push. Preserve three dirty Benchmarks scripts. Do not launch/control the user's app or global input: parent coordinates live validation. Parent coordinates aggregate validation. Any Swift/helper or product compilation must use Kyoto when available, including tests that compile Swift; prepare new cached helpers with `kyoto.py submit -- python3 Scripts/agent-ui/prepare.py` before runtime use. Focused Python-only tests may run without a build. Avoid simultaneous full product builds.
