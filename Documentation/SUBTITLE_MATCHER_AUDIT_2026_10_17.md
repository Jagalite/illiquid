# External subtitle matcher: continuation audit

Date: 2026-10-17. Baseline: PR #8 at `86f5d669f1cfb439143967b5495735e0994d85c3`.
Scope: automatic filename association and its focused regression harness. Subtitle text parsing, decoding, renderer recovery, and media-library recognition are not modified.

## Confirmed cancellation defect

`TokenIndex.candidates` returned an empty array when interrupted. An empty array also means a completed lookup with no candidates. The outer matcher could therefore continue, or finish its last subtitle, and return associations computed before cancellation.

A deterministic reproduction associates `Alpha.en.srt` with `Alpha.mkv`, then cancels while the final `Show.srt` lookup traverses the `Show Episode 1.mkv` / `Show Episode 2.mkv` subtree. Four cancellation checkpoints returned a nonempty dictionary containing the earlier Alpha association. A pre-cancelled invocation containing only unsupported files also returned a dictionary rather than the cancellation sentinel.

The fix gives interrupted lookups a distinct `nil` result, which immediately propagates to an empty public result. Additional checks cover initial result construction, unsupported subtitle entries, prefix traversal, result sorting boundaries, and final return. The scoring and tie-breaking rules from the original PR are unchanged.

This is an all-or-nothing result guarantee **once cancellation is observed**, not a hard latency bound or preemption of Foundation calls. The outer `FolderPlaylistDiscovery.discover` already checks cancellation before and after playlist construction, so this audit does not claim that partial results were observed in the visible player.

## Regression coverage that could not detect a broken index

The original exhaustive-comparison fixture gave every title both MKV and MP4 copies. Every score winner tied, so the expected output contained no assigned subtitles. Replacing candidate lookup with an unconditional empty result still passed that one comparison test.

The new corpus examines all 256 subsets of eight media files, each in forward and reversed input order, against 12 subtitle names. It includes unique winners, equal-score ties, and no-match cases, and asserts that all three categories actually occur. The deliberately empty-index mutation fails 510 comparisons in this corpus. This validates coverage sensitivity; the mutation is not part of the production change.

Additional checks cover cancellation injected at every observed checkpoint (both latched and one-observation predicates), the real current-task cancellation default, release-specific versus generic subtitles, all five supported filename extensions, Unicode/case normalization, duplicate media inputs, and unrelated files. Existing folder-discovery tests exercise real temporary directories.

## macOS CI harness defect

The baseline's [restoration workflow run](https://github.com/Jagalite/illiquid/actions/runs/39004969741) passed `native-lifecycle` but failed `focused-core` before running tests. The generated temporary package did not declare a macOS deployment target. The compiler rejected `Task.isCancelled` and `Task.checkCancellation` as requiring macOS 10.15 or newer.

The temporary manifest now declares `.macOS("26.0")`, matching the repository's root `Package.swift`. Production availability checks are not weakened, and the application's deployment target is not changed. A fresh macOS run is required to verify this correction; the earlier native-lifecycle success is not validation of this follow-up commit.
